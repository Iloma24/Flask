Глава 16: Полнотекстовый поиск (издание 2024)

В этой главе показана как добавить полнотекстовый поиск в приложении
Суть механизма полнотекстового поиска заключается в следующем. Паралельно основной базе данных db (SQLAlchemy), создается
некое отдельное текстовое хранилище именуемое - индекс, создается это хранилище в функции create_app в виде создания нового
атрибута экземпляра приложения - appObj.elasticsearch, я буду называть это хранилище - область поиска. В хранилище
помещается весь текст из db в котором предполагается будет выполняться поиск. Также в модели, из которой планируется
копировать текст для индексации, создается новый атрибут, для данного приложения это атрибут __searchable__ в классе Post
(поскольку в данном приложении планируется выполнять поиск по текстам постов). Атрибут __searchable__ нужен для взаимодействия
между основной базой приложения (db) и областью поиска (appObj.elasticsearch). Атрибут __searchable__ содержит список имён полей
или поля (body) в модели (Post) из которой планируется копировать индексируемый текст, т.е. как бы является инструкцией
для взаимодействия между двумя хранилищами.
Таким образом, поскольку в данном приложении полнотекстовый поиск будет выполняться в постах, то соответственно все записи
постов в столбце body класса Post будут также сохранены в созданном текстовом хранилище/области поиска (appObj.elasticsearch),
т.е. все изменения в постах будут отражатся и в этом хранилище, это называется - ИНДЕКСИРОВАНИЕ. Хранилище (appObj.elasticsearch)
имеет структуру JSON-словаря и словарь этот может состоять из одного или множества отдельных индексов (ключей). Таким образом, эти
два хранилища данных (БД SQLAlchemy и поисковое хранилище) всегда должны быть синхронизированны. Любые изменения данных
в БД, должны быть отражени и в поисковом хранилище.
Для обеспечения синхронности/согласованности между БД SQLAlchemy и elasticsearch-хранилищем, необходимо чтобы отслеживались
изменения выполняемые в БД SQLAlchemy чтобы такие же изменения выполнить и в поисковом хранилище. Для осуществления отслеживания
изменений в БД, SQLAlchemy предоставляет инструмент Events. Events сообщает приложению об изменениях произошедших в заданных
областях БД, это решает проблему обнаружения изменений в БД, а вот для решения второго вопроса - отражения этих изменении
в поисковом хранилище создается кастомный класс SearchableMixin, в котором прописывается вся логика согласования изменений
между БД SQLAlchemy и elasticsearch-хранилищем. SearchableMixin должен быть одним из родительских классов при создании
класса модели (в данной конфигурации приложения это класс Post) в которой планируется выполнять полнотекстовый поиск и тогда
такой объект будет наследовать все возможности SearchableMixin. Для выполнения непосредственно индексирования/измения
(добавление, обновление, удаление) данных в elasticsearch-хранилище, создается модуль search.py
Elasticsearch - это внешний сервис, соответственно у него есть свой URL-адрес и этот адрес должен быть прописан в
переменной окружения, URL-адрес для этого приложения прописан в .env-файле.
Также, для обеспечения работы сервиса, требуется установить библиотеку pip install elasticsearch
После того как URL-адрес сервиса прописан и библиотека elasticsearch установлена, нужно запустить поисковой сервис Elasticsearch,
я запускаю через докер, командой:
    docker run --name microblog-elastic -d -p 9200:9200 -e "discovery.type=single-node" -e "xpack.security.enabled=false" elasticsearch:8.11.1
    разбор команды:
    --name microblog-elastic — дает контейнеру понятное имя, чтобы его было легко перезапускать.
    -d — запускает контейнер в фоновом режиме (демоном), чтобы он не блокировал терминал.
    -p 9200:9200 — указывает порт 9200 из контейнера на localhost:9200 (именно его ищет Flask-код).
    -e "discovery.type=single-node" — переводит Elasticsearch в режим одиночного узла (отключает поиск других серверов в сети).
    -e "xpack.security.enabled=false" — важный флаг для туториала Мигеля Гринберга. Он отключает обязательную генерацию
        паролей и HTTPS, позволяя Flask-приложению подключаться по обычному HTTP без ошибок аутентификации.
    elasticsearch:8.11.1 - версия библиотеки elasticsearch. Если данная версия не срабатывает можно запустить последную,
        заменив последний аргумент на: elasticsearch:latest

    для перезапуска контейнера:
    docker start microblog-elastic
