Структура приложения Microblog в 15 главе «Мега-туториала» Мигеля Гринберга (посвященной рефакторингу, стилизации и
подготовке к развертыванию) представляет собой классическое крупное многомодульное приложение на Flask, переведенное на
шаблон проектирования Application Factory (Фабрика приложений) и разделенное на блюпринты (Blueprints).Такой подход
устраняет проблему циклических импортов и позволяет легко масштабировать проект.

Архитектура каталогов и файлов. Ниже представлена полная схема расположения файлов в проекте на этапе 15 главы:
microblog/
├── app/                  # Главный пакет приложения
│   ├── auth/             # Блюпринт аутентификации (вход, регистрация, сброс пароля)
│   │   ├── routes.py
│   │   ├── forms.py
│   │   └── email.py
│   ├── errors/           # Блюпринт обработки ошибок (404, 500)
│   │   └── handlers.py
│   ├── main/             # Блюпринт основного функционала (лента, профили, посты)
│   │   ├── routes.py
│   │   └── forms.py
│   ├── templates/        # Папка HTML-шаблонов (структурирована по компонентам)
│   │   ├── auth/
│   │   ├── errors/
│   │   ├── _post.html
│   │   └── base.html
│   ├── static/           # Статические файлы (CSS, JS)
│   ├── __init__.py       # Создание фабрики приложений (create_app)
│   ├── models.py         # Модели базы данных (User, Post)
│   └── email.py          # Общие утилиты для отправки почты
├── migrations/           # Папка миграций базы данных (Alembic)
├── config.py             # Класс конфигурации приложения
├── microblog.py          # Точка запуска (главный скрипт)
└── requirements.txt      # Зависимости проекта

Подробный разбор ключевых компонентов

1. Точка входа и конфигурация (Корень проекта)
    config.py: Содержит класс Config. Все настройки (секретный ключ, параметры базы данных, настройки почтового сервера)
        берутся из переменных окружения. В 15 главе конфигурация остается централизованной.
    microblog.py: Главный исполняемый файл. Он импортирует функцию create_app из пакета app и создает экземпляр приложения:
        app = create_app(). Также здесь настраивается контекст оболочки (@app.shell_context_processor) для работы через
        терминал.

2. Фабрика приложений (app/__init__.py)
   Вместо создания глобального объекта приложени app = Flask(__name__), используется "фабрика приложений" (ФП) create_app(config_class=Config)
   2.1 Динамическое создание: Объект приложения создается внутри функции ФП.
   2.2 Инициализация расширений: Расширения (SQLAlchemy, Migrate, LoginManager, Mail, Moment, Bootstrap) объявляются глобально,
       но привязываются к приложению внутри фабрики через метод .init_app(app).
   2.3 Регистрация Блюпринтов: В конце функции ФП регистрируются все архитектурные blueprint-модули (auth, errors, main).
       В этот же момент настраивается логирование ошибок в файлы или на почту.

3. Разделение на Блюпринты/модули (Blueprints)
   Приложение разбито на три изолированные логические части:
   3.1 app/errors/: Отвечает только за перехват ошибок. Содержит handlers.py, где функции декорированы с помощью
       @bp.app_errorhandler, чтобы обрабатывать ошибки 404 и 500 на уровне всего приложения.
   3.2 app/auth/: модуль авторизации. Включает свои формы (forms.py), маршруты (routes.py для login, logout, register) и
       логику восстановления пароля. Все маршруты имеют префикс (например, /auth/login).
   3.3 app/main/: ядро приложения содержит - домашнюю страницу, профили пользователей, подписки и логику создания постов.

4. Обновленная структура Шаблонов (app/templates/)
   Чтобы структура представлений соответствовала коду, папка шаблонов также разделена (app/templates/):
   4.1 Базовый шаблон base.html и подшаблон (вложенный шаблон) поста _post.html лежат в корне папки.
   4.2 Шаблоны авторизации перенесены в templates/auth/.
   4.3 Страницы ошибок перенесены в templates/errors/.
   4.4 При вызове render_template теперь явно указывается подпапка, например: render_template('auth/login.html').

Главные изменения по сравнению с ранними главами
1. Замена appObj на current_app: Поскольку глобального объекта appObj больше нет, во всех модулях (особенно в маршрутах)
   для доступа к конфигурации или ресурсам используется прокси-объект from flask import current_app.
2. Именованные маршруты (Url Routing): При генерации ссылок через url_for теперь обязательно указывать имя блюпринта.
   Вместо url_for('login') используется url_for('auth.login') или url_for('main.index').


Вот как устроена логика его запуска и работы:
    Точка входа в приложение.
        Главный скрипт: Файл microblog.py служит официальной точкой входа (entry point) для всего проекта. Он импортирует
        экземпляр приложения Flask и контекст базы данных, чтобы веб-сервер знал, что именно нужно запустить.

    Что происходит при запуске
        1. Инициализация: Скрипт microblog.py вызывает пакет app (папку app с файлом __init__.py).
        2. Сборка компонентов: Внутри __init__.py создается сам объект Flask, настраивается конфигурация, подключаются
           база данных (db) и миграции.
        3. Загрузка логики: В самом конце инициализации импортируются маршруты (routes.py) и модели данных (models.py),
           чтобы приложение «узнало» обо всех страницах и таблицах.
